# LayoutCanvas · 0.1.0

`CanvasAppearance` defaults to `auto` and accepts `light` or `dark` for deterministic previews. Automatic appearance follows the OS and explicit GTK dark-theme selection. Builtin previews use contrasting text, field fills, borders and selection handles in both modes; package renderers receive `$appearance` alongside their typed values and `$expressions`. Constraint-controlled nested Views retain previews of their declared literal frames while direct dragging stays disabled; this is not a live constraint solver.

The design canvas and inspector accept keyboard focus and expose selection, row values and control names through native accessibility metadata. Tab/Shift+Tab select design controls; arrow keys move the selection. Focus the inspector mode switch and use Left/Right or Space to change modes, then Return to enter its property list. Keyboard focus and native accessibility metadata must be evaluated in the actual host application.

Navigator libraries can call `SelectPaletteType(canonicalTypeName)` to select a control in the tool palette. Selection cancels any old placement, clears a filter that hides the type, expands its section and scrolls it into view. Unknown types return False and leave the palette unchanged. Canonical identities include package-qualified names from discovery. Setting `InspectorMode = "palette"` still works and reveals the palette column.

A reusable native `LayoutEditor Inherits View`, backed by LayoutKit source snapshots and EditorKit edit batches. Import `layoutcanvas`; install its sealed package alongside `layoutkit` and `editorkit`. LayoutKit types require explicit whole-module imports (`layoutkit.LayoutDocument` and `layoutkit.LayoutCatalog`); Buoy 0.72 does not support selective class/interface imports.

The host calls `editor.Catalog.RegisterBuiltinControls()` once, registers trusted compiled extensions, attaches a `LayoutEditorHost` with `AttachHost`, and calls `LoadDocument(New LayoutDocument(document.Text, document.Version))`. Place the editor using `Move`, `LayoutPanel(width, height)` and `AddSubview`. Call `OpenInput()` when the host window opens to enable native wheel delivery, and `CloseInput()` before native widgets are destroyed. `NativeInputError` reports adapter failures. Call `DetachHost` when closing. All native operations belong on the UI thread.

The palette and inspector flank the design surface in native splitter panes. Drag either divider to resize; side widths survive window resizing and panel hide/show within the editor session. Wheel or trackpad scrolling moves the palette and inspector lists and pans the design surface.

Native snapshots share a cache limited to 256 entries and 16,777,216 decoded pixels. Oversized previews use portable drawing when they cannot fit the bitmap limit, so large layout frames do not allocate unbounded native images.

The host implements `CommitLayoutEdits(expectedVersion, edits) As Boolean`, `LayoutSelectionChanged(nodeId)` and `LayoutStatus(message)`. Before applying edits, compare `expectedVersion` with the authoritative EditorDocument revision. Apply the batch as one transaction and reload a fresh snapshot. Rejected stale edits leave source untouched. Undo/redo, dirty tracking and saving belong to the host; reload after these operations too.

Selection, dragging and resizing work on supported literal Frame geometry, including nested plain Views. Child coordinates stay relative to their parent; painting and hit-testing accumulate offsets and clip to ancestors. Descendants of unsupported container types remain read-only. The root picker selects one Window or View in a multi-layout file; `ActiveRootId`, `SelectRoot(id)` and `SelectRootIndex(index)` expose that selection to hosts. Changing roots cancels gestures and invalidates custom editor callbacks.

Gesture previews do not rewrite source; a completed gesture proposes one commit, allowing one undo step. Supported literal property changes replace only source spans. Whole-number input for an existing floating literal is emitted as a floating literal (`1` becomes `1.0`). Unknown properties and expressions stay intact and are never executed.

The inspector has a mode selector switching between Properties, Palette and Constraints views. The Properties mode shows geometry fields, a property picker/editor and rename/delete controls. Rename and delete require the host to also implement `LayoutProjectRefactorHost` from `layoutkit.LayoutRefactor`; without it the controls are disabled with an actionable status. The host performs proven multi-buffer atomic edits; the editor never rewrites references directly. Public headless methods `RenameSelected(newName)`, `DeleteSelected()` and `RefactorAvailable` support testability.

**Tool palette.** A dedicated column left of the canvas lists every catalog control, including discovered package descriptors. Each row shows the control's `LayoutCatalog.IconFor` icon and display name. Controls are grouped into collapsible sections by `LayoutControlDescriptor.Category`, in `Catalog.Categories()` order. The column has a native search field that filters on name, type, category, package and description, and a toggle between the icon list and a compact icon grid. Hovering highlights a row, and a footer describes the hovered or selected control. The column is drawn in the canvas light/dark appearance and scrolls with a drawn scrollbar or the keyboard, because `Canvas` has no wheel event.

Palette interactions:

- **Click** arms placement. The armed item is highlighted, and the next click on the canvas places the control there. Clicking the item again, or pressing Escape, disarms it.
- **Double-click** or **Return** inserts the control at a cascading default position inside the selected `View`, or in the active root.
- **Dragging** an item out of the column onto the canvas drops it at the release point. If the platform stops reporting the drag after it leaves the column, the item is armed instead, so a click still places it.
- **Keys**: Up/Down move the selection (by row in grid mode), Left/Right collapse or expand the section in list mode, and PageUp/PageDown/Home/End jump. Typing printable characters edits the filter, and Backspace removes the last character. Space arms or disarms the selection.

Names come from the type with a unique numeric suffix (`textfield1`); rename them in the inspector. `PerformAction("insert")` and `PerformAction("arm")` act on the palette selection. The editor commands `toggle-palette` (collapse or show the column) and `palette-search` (show the column and focus its search field) are routed through `PerformCommand`. Headless and host API: `PaletteFilter`, `PaletteGridMode`, `PaletteVisible`, `PaletteSelectedType()`, `PaletteArmedType()`, `PaletteVisibleTypes()`, `PaletteSections()`, `PaletteCategoryCollapsed(category)`/`SetPaletteCategoryCollapsed(category, collapsed)` and `PaletteItemFrame(typeName)`. `RefreshCatalog()` re-populates the palette after the host mutates the catalog.

`InsertControl(parentId, typeName, controlName, x, y, width, height)` is the public headless insertion API. Insertion emits the bare source type name and the `sourceImport` from descriptor metadata, preserving source comments in one undo transaction. Default property values are decoded from descriptor `DefaultExpression` to typed JSON scalars; enum and constructor-argument defaults are skipped. `ArmPlacement(typeName, controlName)`, `DisarmPlacement()` and `PlacementArmed` control click-to-place mode.

The Constraints mode lists, adds, edits and removes constraints on the active root using structured typed fields for node, anchor, relation, offset and priority. Constraints are supported only on Window roots; standalone View roots show an actionable status because the compiler does not support View-root constraint lowering. Public methods `Constraints()`, `AddConstraint(...)`, `EditConstraint(...)`, `DeleteConstraint(constraintId)` and `ConstraintsSupported` are exposed for headless testing.

Builtin component previews use cached OS-drawn images on all three desktop platforms (`LayoutCanvasNative`). macOS snapshots AppKit views in a never-shown host, with scoped appearance and initialized bitmap storage; GTK4 snapshots children of an undecorated, fully transparent host into GSK textures; Windows sends `WM_PRINT` to controls under a never-shown, nonactivating parent and reads a DIB. These paths do not execute project constructors, capture the desktop, require Screen Recording permission, or pump the editor event loop. Each component can move, reorder and be selected without rendering again. Size, visual values (including enabled state and fonts), appearance context and raster density form its cache identity. The editor passes the current window's backing scale on each paint. Native theme/default-font context on GTK, system colors on Windows and accent/contrast on macOS are included in render identity; hosts can call `InvalidateNativeRendering()` for other appearance changes. `NativeRenderingError` exposes a native failure while portable drawing remains available.

Native controls cover buttons, labels, fields, pop-ups/combos, checks/radios, sliders, steppers, progress bars, date pickers, tabs and empty list chrome; the Inspector's mode switch uses native segmented/toggle buttons. Date values, tabs and radio-group entries remain representative design-time samples rather than evaluation of project expressions or data. The date picker and stepper use the same platform widget families/compositions as Buoy (GTK menu button/two arrow buttons; Windows date/time composition/up-down; AppKit picker/stepper). GTK previews use the configured GTK theme with the requested light/dark variant. Windows supplies a canvas-matching opaque background because GDI does not return useful alpha; themed control chrome follows what Windows supports in the running session. Source-loaded images, HTML/GPU surfaces, custom controls without a registered painter and chrome the runtime draws itself (GroupBox and Windows disclosure chevrons) keep portable/package rendering. Container children remain canvas nodes; native previews do not instantiate their source children or solve runtime constraints. `NativeControlRendering = False` forces portable previews everywhere. Package renderers continue to paint through `IGraphics`; third-party registration is explicit compiled code, separate from package installation.

Custom editor Views should implement LayoutKit's `LayoutReusablePropertyViewV1.RebindProperty(currentExpression, host)`. Build native children once, then replace displayed values and callback hosts on rebind. Each new host is snapshot-bound; never retain or reactivate the previous host. The editor caches one reusable view per factory. Buoy currently exposes no public removal API, so legacy non-reusable factories have a lifetime cap of 16 allocations per LayoutEditor and then use the registered nonvisual editor or generic literal editor. `CustomViewCount` exposes the retained view count. DesignerWidgets demonstrates reuse across repeated selections and reloads.

The native custom-editor slot is 68px high, with width equal to the inspector
width minus 24px (196px at its normal minimum). Keep child controls within that
allocation. Bindings also implement `LayoutPropertyEditorContextV1`: read sibling
source expressions from the same immutable snapshot and check `IsCurrent()`
before a no-op. These are data, never executable expressions. All edits still
pass through `CommitExpression` and its revision/selection checks.

If a native factory or reusable view throws, its binding expires and that factory is disabled for the editor instance. The registered nonvisual editor or generic literal editor remains available when the selection is still current. A plugin-triggered reload or selection change keeps the new inspector intact instead of restoring the old selection's fallback.

[DesignerWidgets](https://github.com/BuoyBay/designerwidgets/blob/main/modules/DesignerWidgets.bui) demonstrates an independently packaged custom Canvas control, renderer and native two-button property editor. The [host demo](https://github.com/BuoyBay/layoutkit/blob/main/examples/layout_designer_demo.bui) explicitly registers builtins and DesignerWidgets, shows the editor, and provides Undo, Redo and “Mark saved (memory)” buttons. The latter only records an in-memory baseline; it writes no file.

Linux consumers using the installed Picture backend require a compatible JPEG ABI 8 runtime. Configure the native loader for its real installation directory when it is not on the standard system search path.

On macOS 27.2, AppKit's off-screen light text-field drawing can omit the straight bezel edges while a visible native field draws the full border. This also reproduces in a standalone Swift/AppKit capture with Increase Contrast disabled; dark fields and search fields retain their full bezels. It is a remaining snapshot fidelity limitation, independent of selection and resize handles.
